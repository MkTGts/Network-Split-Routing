# Исключения из HAPP через текущий интернет-шлюз

Набор скриптов для Linux с NetworkManager. Он направляет указанные сайты и IP-сети напрямую через обычный интернет-интерфейс, а остальной трафик оставляет на основном маршруте системы — например, через `happ-xray`, если включён HAPP.

Обработчик не меняет настройки подписок HAPP и не отключает VPN. Он добавляет более точные маршруты в таблицу Linux. Такой маршрут выигрывает у общего маршрута по умолчанию только для перечисленных адресов.

## Как это устроено

1. `install.sh` устанавливает обработчик в `/etc/NetworkManager/dispatcher.d/90-ktalk-wifi-route` и список ресурсов в `/etc/network-split-routing/resources.conf`.
2. При первой установке он сохраняет имеющиеся `~/.config/Happ/routing.json` и `subs.db` в `~/.local/state/network-split-routing/happ-before-install/`. Каталог и файлы доступны только владельцу. Повторная установка не перезаписывает этот снимок.
3. NetworkManager запускает обработчик при подключении/отключении сети и при обновлении DHCP. Отдельный демон или таймер не нужен.
4. При событиях подключения обработчик читает IPv4-маршруты по умолчанию, пропускает `happ-xray` и `lo`, затем выбирает интерфейс с наименьшей метрикой среди оставшихся маршрутов.
5. Шлюз берётся из выбранного маршрута. Для IPv6 обработчик запрашивает шлюз у NetworkManager и, если это не удалось, смотрит существующие IPv6-маршруты интерфейса.
6. Обработчик направляет заданные сети и текущие DNS-адреса заданных доменов через этот интерфейс. На отключении сети он удаляет созданные им маршруты для отключившегося интерфейса.
7. Созданные маршруты и интерфейсы записываются в `/run/ktalk-wifi-routes`, чтобы их можно было безопасно удалить или заменить при следующем сетевом событии. `/run` очищается при перезагрузке; NetworkManager создаст маршруты снова при подключении сети.

Если HAPP включён, его общий маршрут остаётся маршрутом по умолчанию. Для адресов из списка более конкретный маршрут через Wi-Fi/Ethernet имеет приоритет. При выключенном HAPP исключения тоже идут через обычный интерфейс, а остальной трафик следует обычному системному маршруту.

Если одновременно доступны несколько не-HAPP маршрутов по умолчанию, выбирается тот, у которого меньше метрика. Если другое VPN-подключение объявляет такой маршрут, оно тоже может быть выбрано.

## Состав файлов

- `install.sh` — установка; требует NetworkManager и `iproute2`.
- `dispatcher.sh` — логика выбора интерфейса и установки маршрутов.
- `resources.conf` — ресурсы, направляемые напрямую. Его формат описан ниже.
- `uninstall.sh` — удаление обработчика и созданных маршрутов. Файл ресурсов в `/etc/network-split-routing/` сохраняется, чтобы не потерять пользовательские изменения.

## Установка

Требуются Linux, работающий NetworkManager, Bash, `ip` из `iproute2` и `getent`. `nmcli` нужен для более надёжного определения IPv6-шлюза; без него скрипт попробует найти шлюз по существующим IPv6-маршрутам. Для установки нужен администраторский доступ.

Из каталога с этим README:

```bash
sudo ./install.sh
```

В графической сессии можно также запустить `./install.sh`: если доступен `pkexec`, он запросит системную авторизацию.

Установщик копирует скрипт и начальный список ресурсов. При повторной установке существующий `/etc/network-split-routing/resources.conf` сохраняется. После установки обработчик сразу применяет список к текущему подключению; затем NetworkManager будет запускать его автоматически при сетевых событиях.

Установленные пути:

```text
/etc/NetworkManager/dispatcher.d/90-ktalk-wifi-route
/etc/network-split-routing/resources.conf
/run/ktalk-wifi-routes
```

## Список ресурсов и добавление новых

Редактируйте системный файл:

```text
/etc/network-split-routing/resources.conf
```

В файле поддерживаются три записи:

```text
host example.com
route4 203.0.113.16/28
route6 2001:db8:1234::/48
```

- `host ИМЯ` — при запуске обработчика разрешает имя через DNS и ставит маршруты к его текущим IPv4-адресам `/32` и IPv6-адресам `/128`.
- `route4 СЕТЬ/CIDR` — направляет через выбранный интерфейс всю указанную IPv4-подсеть.
- `route6 СЕТЬ/CIDR` — направляет через выбранный интерфейс всю указанную IPv6-подсеть, если удалось определить IPv6-шлюз.
- Пустые строки и строки, начинающиеся с `#`, игнорируются.

Например, чтобы направить `portal.example.net` и его отдельный API-хост напрямую:

```text
host portal.example.net
host api.example.net
```

Запись `host example.net` **не означает** автоматически `*.example.net`: DNS-имя не перечисляет все поддомены. Добавьте используемые поддомены отдельными строками `host` либо укажите опубликованные поставщиком подсети через `route4`/`route6`. Подсетный маршрут охватит все адреса в диапазоне независимо от имени сайта.

После изменения файла примените его без переподключения сети:

```bash
sudo /etc/NetworkManager/dispatcher.d/90-ktalk-wifi-route __manual__ up
```

Новые DNS-адреса для `host` обновляются при следующем сетевом событии или при этой ручной команде. Скрипт не следит за TTL DNS в фоне.

### Как добавлять подсети безопасно

Добавляйте только диапазоны, опубликованные владельцем сервиса как его собственные адреса. Не добавляйте большие диапазоны облачного провайдера целиком: в них могут находиться сайты других организаций, и они тоже пойдут напрямую.

Текущий список содержит подсети Контур.Толка и опубликованные Яндексом диапазоны. Для Толка он учитывает сеть для веба и подсети медиатрафика; для Яндекса — опубликованные диапазоны собственных сервисов и отдельные имена с DNS-ответами за их пределами. Источники списков могут обновляться:

- [Технические требования Контур.Толка](https://support.kontur.ru/talk/41117-texnicheskie_trebovaniya)
- [IP-диапазоны, принадлежащие и используемые Яндексом](https://yandex.com/ips)

## Проверка

Посмотреть, куда пойдёт конкретный адрес:

```bash
ip -4 route get 77.88.44.55
ip -4 route get 1.1.1.1
```

Для первого адреса должен отображаться текущий обычный интерфейс и, если есть, его шлюз. Для контрольного `1.1.1.1` при включённом HAPP обычно будет `dev happ-xray`.

Проверить IP домена Holst и маршрут к нему:

```bash
getent ahostsv4 app.holst.so | awk 'NR == 1 { print $1; exit }'
ip -4 route get "$(getent ahostsv4 app.holst.so | awk 'NR == 1 { print $1; exit }')"
```

Состояние созданных маршрутов:

```bash
cat /run/ktalk-wifi-routes
```

Журнал обработчика:

```bash
journalctl -t network-split-routing
```

Если список в `/run/ktalk-wifi-routes` пуст, проверьте, что NetworkManager активен и что у системы есть IPv4-маршрут по умолчанию помимо `happ-xray`:

```bash
systemctl is-active NetworkManager
ip -4 route show default
```

## Удаление

Из каталога проекта:

```bash
sudo ./uninstall.sh
```

Либо `./uninstall.sh` в графической сессии с `pkexec`. Скрипт удалит обработчик и созданные им маршруты, восстановит `routing.json` и `subs.db` из снимка до установки, но оставит `/etc/network-split-routing/resources.conf`. Если файл больше не нужен, удалите его вручную после сохранения пользовательских записей.

Снимок HAPP хранится в `~/.local/state/network-split-routing/happ-before-install/` с правами доступа только владельцу. После удаления файлы снимка остаются, а служебная отметка сбрасывается, чтобы следующая установка создала свежий снимок. Так как `subs.db` может содержать данные подписок, восстановление вернёт базу к состоянию на момент установки и отменит изменения в ней, сделанные позже. После удаления перезапусти HAPP, чтобы он перечитал восстановленные настройки.
